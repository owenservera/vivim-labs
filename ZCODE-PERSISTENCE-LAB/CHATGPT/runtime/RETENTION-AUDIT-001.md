# Bounded retention audit and capacity feedback

Base e81c70f531cef9875ab88a01edf00205389c7ed7. E33 source-only. History audit verifies active/archive pairs, agrees surviving duplicate components, checks predecessor record hashes, and compares original commands/responses against current durable request receipts. Up to 256 revisions per window, with optional exact current anchor to fence pagination. Missing pre-checkpoint records are explicit gaps, not proof that older pruning was legitimate. Missing retained records, mismatched checksums or receipt disagreement are errors. A complete window is not a global chain or independent custody proof.

Retention-report accepts programmable entry budgets and optional max archive bytes/index bytes/pin files. Lazy directory traversal reports actual regular-file byte counts or lower bounds when truncated; no symlink traversal, no deletion, no automatic data expiry. An incomplete inventory cannot report within-budget unless the complete area has been visited. Bytes are file lengths, not allocated disk usage. Commands: history-audit START LIMIT [ANCHOR_FILE]; retention-report POLICY_FILE. Sample limits are not mandated. No archive export/custody, capacity enforcement, build, test or benchmark performed.
