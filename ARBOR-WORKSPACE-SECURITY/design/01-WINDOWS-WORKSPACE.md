# Windows workspace security design R002
## Decision
Use distinct privilege domains: installed trusted binaries, owner-authorized Host, isolated workers, dedicated browser broker, encrypted user data, and development checkout. Do not rely on folder naming or same-user DACLs alone. Prefer per-worker AppContainer or a restricted separate identity with explicit resource ACLs; evaluate Wasm for portable pure transformations. Job objects constrain resources and process lifetime, but are not security boundaries. No administrator requirement in normal product operation. Determine actual Windows version and compatibility before picking implementation. Reference: https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer.
## Provisioning
Extend the existing workspace manifest and supervisor, do not create a competing workspace model. Map actual data roots and runtime files; validate OS ownership, canonical identity, location, ACL and required capabilities. Reject ambiguity rather than falling back to another browser or user profile. Separate immutable release content from user data and development. Do not inherit parent secrets, current directories or arbitrary handles into workers.
## Filesystem broker
Resources registered by opaque ID, not model-provided absolute path. Resolve against owner-approved roots with OS handles and verify final-object identity; reject traversal, alternate data streams, device paths, unsafe reparse points and unexpected link targets. Avoid validate-then-open races; authorize the same handle used for the effect. Stage writes, enforce expected revision, atomically publish, flush and receipt. Workers get only task-specific input/output resources.
## Crypto and persistence
Generate independent keys for workspace data and devices; wrap under OS-protected root; use established AEAD with unique nonces, AAD binding workspace/object/schema/version and authenticated metadata. Cover journals, WAL, indexes, temporary data, backups and logs. DPAPI user-scope alone does not isolate same-user workers. TPM is optional capability, not required assumption. Offline encrypted recovery material, explicit key rotation and recoverable migration. No silent reset on corruption. Verify old and new storage readback before switching; keep protected rollback snapshot.
## Acceptance
Normal install needs no privileged manual setup; worker cannot read another workspace, browser profile or vault; Windows path/reparse/race cases fail closed; normal approved save works; crash before/after migration switch preserves old data; restore works on clean device. All runtime checks UNRUN.
