# HQ deep research — the development-intelligence compiler plane

## Existing code and responsibilities
`hq/lib/arbor-service.mjs` scopes developer roots and rechecks per-operation Host authorization. `indexer.mjs` + `schema.mjs` own rebuildable SQLite/FTS indexing; `graph.mjs` reads resolved source dependencies. `semantic-registry.mjs` provides typed, versioned, owner-promoted IDs; `annotation-v2.mjs` parses source tags but **does not compile embedded Rust**. `capabilities.mjs` inventories source manifests without executing them. `context.mjs` produces small, deterministic, provenance-bound context bundles. `wiki.mjs` derives a local development Wiki.

An existing `comment-wiki-bridge.mjs` and Rust-comment adapter translate reviewed *metadata/configuration*, not arbitrary Rust functions. `hq/lib/kernel/store.mjs` is a separate durable HQ kernel store; do not confuse it with the rebuildable index or the Host personal World writer.

## What this changes for VEC
HQ should become the **development-time VEC SDK knowledge factory**:
1. Source scanner discovers optional capsule definitions and explicit comment-scoped semantic IDs.
2. Reconstruct verified source blob SHA and approved toolchain/configuration; no comment grants authority.
3. Existing registry resolves owner-approved IDs and dependencies; SCF adds candidate capability passports.
4. Future independent SV verifies claim/oracle and compiled artifact correspondence; source author cannot approve their own claims.
5. A reviewed build publishes a **portable SDK manifest** containing typed inputs/outputs, risk, capability availability, source/artifact digest, version and verification state.
6. Host installs the accepted manifest and binds it to live runtime capability handlers; the user's personal phrases/data/receipts never enter HQ's development index.
7. The Wiki explains the source of capabilities and SDK compatibility, but does not assert successful user effects from source descriptions.

## Important optimizations
**Stop paying repeat reasoning cost:** exact synonyms and argument grammars, reusable intent patterns, small context bundles, typed dependency crosswalks, static capability passports and deterministic explanation templates. **Measure before Rust rewriting:** HQ FTS write amplification, source change detection, context-ranker cost and graph-query traversal. A Rust port is worthwhile only if CPU/RSS savings beat FFI, disk/build footprint and maintenance cost.
