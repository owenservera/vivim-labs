## What the core must know about VIVIM

- **Identity/provenance:** repository/source/native IDs, pinned revision/digest, namespace and owner, explicit missing evidence. Development and personal domains must not accidentally share identity/cache entries (`src/scoped_graph.rs:32-95`; `tests/typed_dag.rs:101,151`; Harness integration note `:11-13`). Adapters authenticate claims; structurally valid provenance is not authentication (`src/scoped_graph.rs:1-3`).
- **Semantics/change:** typed relations, source-owned projections, tombstones, dependency invalidation, epoch/version and compatibility defaults. Graph indexes are derived (`src/lib.rs:183-190`), not another authority. Reconcile removes owned absent edges, never implicit absent nodes (`src/import.rs:380-413`).
- **Durability/recovery:** distinguish valid prefix, trailing corruption, additive delta, snapshot and explicit repair; keep stale CAS refusal and non-executable descriptors (`src/lib.rs:920-979,1027-1082,1094-1134`; durable tests above).
- **Permissions:** accept only owner-approved, adapter-authenticated data for personal journeys; return inert computation/evidence, never grants. Host remains data/action/approval/receipt owner and Studio browser effect owner (Harness roadmap `:11,139-141`). Rust's central role is computational and semantic integration, not an implied takeover of these authorities.
- **Context/query/programmability/observability:** carry source freshness, exclusions, budget/omission, policy revision and uncertainty to existing callers. W04 requires scoped ingestion→revision/revocation→World search→phone evidence (Harness roadmap `:58`); native crosswalk must preserve action IDs/risk/approval requirements (Harness integration note `:27-32`). Browser sessions, private payload capture, UI publishing, device enrollment and action execution stay outside this crate.

## Ranked engineering priorities

1. **Close HQKGX1 record-order asymmetry with a regression first.** Parser checks node-before-edge using `seen_edges`, but tombstones do not transition that phase; tombstone conflict checks only nodes already seen (`src/import.rs:215-238,280-293`). Current conflicting-ID test uses node→tombstone only (`tests/import.rs:184-198`). Candidate: valid digest/counts with tombstone→node for the same canonical ID must return conflict/invalid, not an Exchange whose apply inserts then deletes that node. Also cover edge after tombstone. This is source-derived risk, NOT an executed failing test. After proving red, implement a monotone nodes→edges→tombstones phase and symmetric identity collision rejection without changing legacy optional defaults. This is the first concrete action, pending a Rust write assignment and foreign-lane clearance.
2. **Make trusted mutation entrypoints and atomicity explicit before more ingestion.** Public `put_*` rejects reserved keys (`src/lib.rs:168-181,224-232,272-278`), but raw public change-set `apply` deliberately bypasses it, permits partial mutation and relies on caller validation (`src/graph_change_set.rs:198-216,367-413`). Scoped validation checks required stamps but does not reject arbitrary additional `hqkg.exchange.*` keys (`src/scoped_graph.rs:71-95,154-174`). Public `Exchange` fields permit construction without parse (`src/import.rs:19-39`); `Exchange::apply` mutates sequentially and can encounter a late owner conflict (`:336-413`). Specify trusted/internal vs untrusted API use and test late failure on the actual supplied graph, scoped extra reserved keys, ordinary overwrite/removal of an imported record, and replay preservation. Existing collision tests inspect an untouched original rather than the failed staging graph (`tests/import.rs:45-57,162-179`). Do not claim a remote exploit: trust/authentication belongs to adapters and current CLI already stages.
3. **Deliver one product-value integration slice using existing capabilities.** Target W04 provenance-bound memory/search/context evidence, not a new store or general rewrite. Agree HQ-data/Host adapter inputs, outputs, source revision and revocation behavior; demonstrate approved source→existing computational surface→existing Host/phone projection. Native compiler crosswalk is a separate compatibility gate, not proof that HQKG must replace it. Until runtime authorization exists, produce a bounded synthetic differential fixture and exact missing adapter, not new product functionality. Harness roadmap `:41,58` and integration note `:27-32` define outcome.
4. **Prove recovery/epoch semantics at mixed-path boundaries.** Tombstone/reconcile happy/idempotent coverage exists (`tests/import.rs:108-179,261-378`); broaden to deletion with foreign-owned incident edges (remove_node cascades indiscriminately: `src/lib.rs:304-324`) and failed mixed batches. Characterize legacy HQJ1-tail recovery versus HQD1 refusal, restart, stale writer and byte/epoch CAS. `Journal::save` deliberately recovers legacy tails but refuses delta tails (`src/lib.rs:1049-1065`; `tests/core.rs:48-61`), so universal tail refusal is a compatibility decision, not a discovered missing guard. Do not silently change it. Full crash/power-loss and Windows filesystem guarantees remain unproven here.
5. **Accept causal-observability work, then measure the actual consumer.** Parent reconciles the foreign lane and its tests before any keeper edits to that module. Measure end-to-end W04 usefulness and provenance correctness as well as computation, ingest, cache hit/miss and journal cost. Do not reopen speed as the architecture premise without real G2/consumer telemetry.
