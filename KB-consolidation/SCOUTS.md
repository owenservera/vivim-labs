# Scout fan-out — not launched

A. **Repos HQ**: code index, semantic identity, wiki, KB/kernel, SQL/FTS, event lake, Rust graph/algorithms, provenance, catalogues, schema and engine adapters.
B. **Harness**: Host data stores, World/KB, grants/effect receipts, sessions, browser/CDP, pairing, mobile relay, agents/workflows, files, runtime caches, local transports.
C. **TierFlow / UI programmability**: World and UI schema, documents, commands, CAS revisions, Studio/editor state, templates, renderer projections, publishing, migration, cross-device sync.
D. **Labs / old inventories**: Observatory, existing registries, task lists, schemas, archives, historical code/data and telemetry; preserve measured counts.
E. **Transport + transformation cross-cut**: IPC, CDP, HTTP, WebSocket, SSE, events, sync, adapters, schema transforms, identity propagation and security.
F. **Writer / model conflict verification**: trace actual reads/writes and stores; classify redundant vs complementary systems and schema evolution/migration risks.

Each scout emits machine-readable records with stable ID, source repo/path/SHA, type(s), owner, authority, reader/writer, input/output schemas, transformations, transport, retention, trust boundary, consumer, status, evidence and open questions. Produce explicit edges and unknown/unlocated cases; no invented links.

Final integration produces: source census, schema registry, store matrix, transport map, transformation pipeline, engine inventory, writer-overlap matrix, graph topology, disposition report and upgrade backlog. Do not replace canonical HQ infrastructure; identify measured gaps first. No source writes, destructive merges, production activation or scouts launched by this scaffold.
