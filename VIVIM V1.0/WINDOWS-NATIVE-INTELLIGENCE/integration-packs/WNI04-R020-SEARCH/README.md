# WNI04 R020 — Windows Search and Shell property proof adapter

Existing Windows SystemIndex OLE DB (read-only) and Shell.Application COM, with fixed property allowlist. Microsoft primary docs: https://learn.microsoft.com/windows/win32/search/using-sql-and-aqs-to-query-the-index ; https://learn.microsoft.com/en-us/windows/win32/search/-search-sql-folderdepth . Context7 windows-rs 0.61.0 gave only general binding guidance, not a usable ADO interface example. PowerShell 7 is deliberately used as a minimal existing-runtime proof bridge, not a new mandatory dependency or canonical production language; eventual native Rust COM/OLE DB adapter should reuse the verified contract.

Caller supplies a trusted approved canonical local fixed-drive root; exact filename, bounded TOP, no caller SQL. Revalidate actual file existence, lexical containment, non-reparse ancestors and protected name policy before any projection. Only relative path, current size/time or fixed Shell properties. Index coverage is always incomplete, unavailable is explicit, no index settings changed. Host must additionally bind handle identity and current grant, enforce existing protected path policy and kill the helper on deadline. Path checks are not race-proof confinement. No search results from outside the approved root. No contents or arbitrary property names.

Test-WindowsIndex.ps1 performs seven fixture checks and attempts real Windows index query and actual Shell properties in a new owned scratch folder. Zero rows is not failure if folder isn't indexed, and provider unavailable is not live query acceptance. No production Host, MCP or GPUI registration. No ARBOR changes.
