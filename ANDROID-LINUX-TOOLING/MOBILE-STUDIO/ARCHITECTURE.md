# Candidate architecture
The existing 12-operation Termux bridge is a compute worker, not a cross-app permission authority. Source candidate: ARBOR tools/mcp/vivim-arbor/android/vivim-android-runtime.cjs at 8fccdbe85678d37aa50293b4ce877fb2eae14dc4, located via GitHub search. Runtime 0.3.0 is observed; deployed binary/source equivalence not yet proven.

Propose a minimal Android companion using Kotlin/Java for framework boundaries (Rust via JNI for SDK, policy evaluation, semantic IR and graph state). Keep existing Product Host contracts and the single GPUI product renderer; permission dialogs and OS surfaces are Android-owned, not a second product UI. Prefer local authenticated IPC with explicit caller validation; no exported generic shell or unrestricted remote service. No separate cloud service required for local capabilities.

Flow: authorized user request -> Product plan -> capability descriptor + policy + Android permission/target check -> user-directed native action -> typed receipt -> local semantic graph projection. Revalidate capability and grant before every effect, and when returning from user selection. Do not treat a permission as authorization for every action. Remote discovery returns descriptors, not personal content by default.

Capability descriptor candidate: stable ID, provider and source revision, supported OS/API, target identity, supported operation, typed input/output, permission/scope, consent mode, effect class, precondition, observation freshness, evidence state, revocation behavior and receipt correlation. For UI-derived semantics: window/session identity, node roles and supported actions, observed state revision and invalidation; never replay against a stale surface. Prefer exported app contracts, intent resolution and explicit shares; pixel capture is observation, not input privilege.

For distribution: Google Play restricts autonomous decision-making via Accessibility API for ordinary apps. Do not design general agent operation around that API; evaluate narrow user-directed/static rule workflows and owned instrumentation fixtures separately. No falsely declaring accessibility-tool status, no bypass via debugging/root. Sensitive data is local, minimized, redacted and never published in Labs. The Android sandbox and secure windows are hard boundaries.

Lifecycle: WorkManager for eligible deferred tasks, typed foreground service only for appropriate visible sessions, durable checkpoints and recovery. User stop/revoke terminates capability; no hidden persistence. Unknown effect state requires reconciliation, not blind replay.
