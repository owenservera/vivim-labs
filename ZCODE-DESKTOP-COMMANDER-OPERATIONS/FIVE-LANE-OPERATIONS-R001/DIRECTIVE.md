# FIVE-LANE OPERATING DIRECTIVE — R001

Applies to every lane. **This is a scoped execution package, not a new job scheduler, provider router, Host, ownership register or product backlog.**

1. **Source of truth:** authenticated `owenservera/ARBOR` `main`; product progress [#33](https://github.com/owenservera/ARBOR/issues/33), [#32](https://github.com/owenservera/ARBOR/issues/32), [#31](https://github.com/owenservera/ARBOR/issues/31); historical/physical acceptance `docs/product/CANONICAL-SURFACE-100-STEP-LEDGER.md`; ownership overlay `ZCODE-DESKTOP-COMMANDER-OPERATIONS/TASK-CLAIMS.md`. Never add 71 + 100 + 37 as separate backlogs.
2. **One primary source writer:** ChatGPT Dev integrates Rust-first application code (TypeScript 7+ only where sensible) on GitHub `main`. Lane operators may inspect/test and prepare limited Labs packets in parallel. ARBOR edits require the exact latest source and explicit active task/file claim with nonoverlapping scope. No extra PR/branch, force-push, blind local reset or claimed-file collision.
3. **Only one Host/Studio authority:** Host owns grants, effects, approvals, journal, revisions and receipts; incumbent signed-in Studio Chrome profile owns browser/provider operations. No provider APIs, Playwright, duplicate dashboard or second engine. No unapproved send, browser-recording, credential access, personal corpus ingestion, account effects or phone release.
4. **Model policy:** reuse ZCode's *existing* registry and auto-fallback. Configured != verified-working; no silent paid route. Check live admission/quota/cost before a model call. Read-only deterministic work is the default.
5. **Concurrency:** Five lanes may independently plan and inspect. **Begin with at most two simultaneous read-only ZCode model workers** after verified availability, then scale only with actual run IDs, liveness and cost receipts. Never claim five workers alive just because five folders, agent files or DWFs exist. No duplicate scheduled observers.
6. **Prompt/session handoff:** one session per lane, unique lane ID on all outputs. A GitHub handoff/issue comment is a discoverable message, not automatic receiver wake or acceptance. `OFFERED_TO` requires a recorded `ACCEPTED_BY`. Do not write private messages into tracked files.
7. **Evidence ladder:** `PROPOSED → CLAIMED → CODED → PUSHED → SOURCE_TESTED → PACKAGED → SERVING → HOST_ACK → PROVIDER_VERIFIED → GPUI_VERIFIED → PHONE_RENDERED`. A stage may remain blocked; don't fill later stages with inferred PASS. For every reported result include SHA, test command, test total, exit code, runtime identity when relevant, timestamp, blocker and next exact action.
8. **Stop / hand back:** dirty/divergent source, overlapping claim, unverified cost, stale provider thread, uncertain send, unavailable browser owner, local draft/approval in progress, runtime mismatch, missing rollback, or untrusted receipt. Report the blocker and continue only independent no-effect tasks.
9. **Mandatory 3-era report:** ERA 1 observed baseline and claims; ERA 2 actual output with evidence; ERA 3 next claimable actions and clean handoff. Share substantive evidence to existing #33, and only edit an existing checklist on genuine completion.
10. **No impersonation:** directives/prompts do not self-start another ChatGPT conversation, ZCode session, workflow run or background daemon. Explicitly record `NOT_STARTED`, `READY`, `RUNNING_VERIFIED`, `BLOCKED` or `DONE_VERIFIED`.
