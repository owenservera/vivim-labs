# ARBOR — Complete minimal programmable PWA
**Purpose:** make VIVIM itself the baseline visual program, not an empty canvas or another dashboard. Retain working features, make all visible instances semantically addressable, connect existing UI engines and TierFlow, and persist authorized customization through Host.

## Run this package
1. [MASTER-UPGRADE.txt](MASTER-UPGRADE.txt) — launch specification and execution order.
2. [BASELINE-DESIGN.md](BASELINE-DESIGN.md) — complete design, component inventory, navigation, interaction and engine priorities.
3. [CURRENT-BASELINE.md](CURRENT-BASELINE.md) — pinned executable source evidence and overlap.
4. [INTEGRATION-CONTRACT.md](INTEGRATION-CONTRACT.md) — shared identity, rendering, authority and ownership.
5. [PRODUCT-ACCEPTANCE.md](PRODUCT-ACCEPTANCE.md) — real product scenarios and regression requirements.
6. [catalog-inventory.json](catalog-inventory.json) — exhaustive declared taxonomy/engine IDs, source mapping and truthful status; not a runtime manifest.
7. Launch assigned prompts in [lanes/](lanes/). B01–B08 are the implementation round; B09 is final integration and actual product proof, not an audit.
8. [manifest.json](manifest.json) — inventory and baseline metadata.
