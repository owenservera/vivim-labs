# WNI02 R013 — deterministic scheduling and ETW decoding

Actual Rust scheduler uses snapshot freshness, CPU pressure, memory/disk reserve, existing reservations, bounded tasks and stable priority ordering. It proposes admissions, never grants or launches tasks; integrate an atomic reservation and current approval check in incumbent Host. CPU counters are group-scoped; do not feed group-local metric as whole-machine pressure on multi-group hosts. ETW decoder accepts only owned producer closed numeric UTF-16 payload, correlates process creation identity plus generation and sequence, refuses gaps/duplicates/foreign events. Native ETW consumer still pending; producer identity must be verified from actual record and owned session, not caller input. No trace session or system-wide collection. Context7 windows-rs 0.61.0 generic ETW guidance; source-specific payload contract from existing etw.rs. Rust fixture tests pending.
