# ARBOR implementation / VIVIM Product fast-forward boundary

Owner direction — 2026-11-26.

- ARBOR: implement, wire, execute and independently verify live capabilities through Host and Harness. Craft is discovery instrumentation, not independent acceptance.
- VIVIM Labs: maintain the sanitized capability journal, evidence references, source mapping, dependencies and migration dispositions in the existing Craft adapter.
- VIVIM Product: no modifications, commits, migrations or experiments by this workstream. Read-only interface research when needed.

For each capability record stable semantic ID, shared primitive, ARBOR source paths and commit, dependencies, Host authority/effect contract, Rust portability, Meta-VLANG SDK operator mapping, test procedure, live receipt and postcondition, and any Product-specific adaptation. Separate portable logic from ARBOR-specific glue. Never equate ARBOR acceptance with Product acceptance.

Lifecycle: discovered → extracted → generalized/deduplicated → wired in ARBOR → independently executed through VIVIM Harness → real state verified → registered → migration candidate. Missing stages stay open. Direct Craft execution alone does not prove Harness acceptance. Preserve Host approval, receipt, recovery and browser ownership; no synthetic live acceptance or private content in Git.

Product handoff is an inert versioned manifest referencing verified source revisions, portable artifacts, replayable tests and explicit unknowns, not a Product patch. Adoption is separately authorized. Maintain one incremental journal rather than duplicate trackers.

Initial Facebook baseline: Craft observed home, Messenger, account menu, Settings & privacy and Settings. Independent ARBOR Harness acceptance remains open. Generalize permitted app primitives without weakening the existing Harness session constraints.
