# WhatsApp companion — first user-operated vertical slice

Owner objective: interact with existing WhatsApp chats via VIVIM APK and ultimately through the shared Host/PWA interface. Preserve the first read test (three latest chats, three messages each, no full export). No promise of unrestricted background access to personal WhatsApp.

v0.4 adds a native local WhatsAppActivity and non-exported SnapshotService to the existing Rust wrapper. Supported actions: foreground open, text draft routed to WhatsApp's existing-chat picker (ACTION_SEND), and direct chat link using explicit international number. Draft dispatch is not a send receipt. User reviews recipient and text and presses WhatsApp's Send. No automated reply or background send.

Read path: explicit Android MediaProjection consent for each session, user instructed to select single WhatsApp app rather than entire screen. Platform does not provide this prototype a trusted package identity for the chosen capture; preview must be checked by owner. Visible foreground service, one non-black visible frame after short settling interval, capped resolution 1600 pixels longest side, 12-second timeout, stop/release on callback. In-memory bitmap only; local preview and clear. No Internet permission, persistence, OCR, remote upload, private database access, accessibility permission, notification reading, root, or hidden off-screen third-party streaming. If selected window stops producing frames or remains hidden, timeout is valid evidence. Actual Android capture behavior is not yet verified. No chat messages collected during build. The initial read acceptance still requires navigating visible conversation list and chats with owner consent; no full history export or group membership scraping. Owner can explicitly share a relevant screenshot into ChatGPT for now; automatic remote observation is not implemented.

Next: install same signed candidate; validate Rust ABI and owned Activity before capture; select an owned fixture or non-sensitive WhatsApp screen, verify snapshot, stop and clear; user checks actual target. Then capture three selected chat excerpts, extract only requested fields, account for pinned order and possible mark-read effects. Confirm draft picker without sending; later explicitly authorized self-chat send. Native app APIs/notification replies may extend background interaction subject to permissions. Remote Host integration requires authenticated IPC, scoped operations, revocation and bounded receipts. Do not grant a generic remote capture or send authority.
