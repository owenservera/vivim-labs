# Incremental receipt storage

Baseline 2ebb1342b94be6851d33c512002da99f6ca558b2. Schema 4 commits scalar and ordered directory hashes as a hierarchical content commitment. Existing schemas 1–3 keep their previous complete-state digest semantics. Normal commits build world tables as before but append exactly one receipt to a single adaptive receipt page (or split that page), retaining unaffected page hashes. Receipt directory still rewrites as a whole. Normal schema-4 load materializes world tables but not the full receipt history; retained journal records and replay use point lookup. Signed replay still passes existing scoped authority checks and one-shot claim responses remain non-replayable. Explicit audit-index loads and checks all current pages and checks one unique receipt revision per committed transition. Historical pins work for both schema generations.

Limitations: current world tables are still materialized and serialized; this is incremental receipt mutation, not a fully incremental state engine. The integrity model verifies accessed receipt pages during normal operations, rather than all historical receipt pages on every mutation. Explicit full index audit is separate. Previous archived records are not all chained/audited by audit-index. Full directory fanout cost and unbounded archive/pins remain. Source-only fixtures authored; no compilation, testing or actual performance measurements.
