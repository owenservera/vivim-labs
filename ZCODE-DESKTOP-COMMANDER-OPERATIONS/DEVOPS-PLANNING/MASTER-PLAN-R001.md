## Correct interpretation: compile meaning, not just cache tasks

VLANG is an AI-native semantic protocol over existing real code, with inline declarations/annotations alongside Rust/TS; incremental extraction resolves symbols, types, data, dependencies, capabilities, contracts, operations and evidence into one version-aware semantic model. Existing HQ/KB/SQLite and Rust HQKG own their respective storage/compute boundaries. VSC/VSM/VSG/VIR/Verbs are conceptual vocabulary from original design, NOT instructions to create new registries, parsers, databases, VMs or runtimes. Existing @hq parser and registries are the adoption path; original @v grammar is design history, not an accepted replacement. Code governs executable truth; owner knowledge and evidence retain their existing authoritative writers. Declared/inferred/observed/verified/stale claims remain distinct.

Compile loop: edit/observation → incremental extraction and semantic linking → versioned graph/IR → dependency-aware deterministic context packets, AutoWiki, capability/tool descriptors and live UI projections → stale dependencies identified. Runtime feedback loop: human/agent intent → progressive deterministic language/graph resolution → typed program → independent validation and exact human-readable approval → VEC/native Rust computation + incumbent Host effects → real receipts/evidence → explicitly accepted reusable behavior and fresh semantic projections. The former loop precomputes software understanding even for tasks never executed before. The latter grows the reusable operation vocabulary. Neither is response caching or mere macros. AutoWiki is the human-facing projection and diagnostic of the integrated knowledge/command system, not an independent content engine or semantic writer.

Model-free path covers reindexing, graph queries, context generation, Wiki regeneration, capability discovery, supported NL intent, deterministic reasoning/validation, pure computation, approved execution and verified readback. Optional LLM assistance at the ambiguity/novelty frontier may propose labeled enrichment or new typed programs; it is not required for the model-free path, cannot manufacture facts or approvals, and may never be in validated execution. Near-LLM quality is a testable target in the known VIVIM environment, not demonstrated general intelligence.
