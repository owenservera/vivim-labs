# External services and device trust R002
## Browser
Preserve signed-in dedicated Chrome web-app workflow, no provider API substitution. Existing profile and port checks and ownership lock are useful identity/coordination controls, not isolation. Broker CDP transport behind OS boundary, separate browser lifecycle from untrusted workers. Chrome guidance on non-default debugging profile: https://developer.chrome.com/blog/remote-debugging-port. Validate destination and redirects; restrict uploads to resource grants; clipboard and downloads are brokered; never expose cookie store or raw auth headers to models/workers. Browser session page content is untrusted. Consequential form submits bind exact target and data to Host grant. Separate accounts/profiles where needed; no fallback to personal browser.
## PWA
Reuse existing browser-device-key and enrollment path. Browser WebCrypto nonextractable key in IndexedDB is useful but same-origin hostile script may still invoke it; do not equate it with hardware backing. Require authentic HTTPS origin, proof-of-possession challenge bound to origin/workspace and device, atomic one-use redemption, explicit enrollment approval and session expiry/revocation. Consider WebAuthn for owner step-up, not mandatory replacement of working key flow. Never persist session bearers in localStorage. Minimize sensitive offline caches; service worker should cache only explicitly public shell assets, not personalized responses. Validate CSP, trusted UI separation and CSRF/origin boundaries. References: https://developer.mozilla.org/en-US/docs/Web/API/CryptoKey and https://developer.mozilla.org/en-US/docs/Web/API/Web_Authentication_API.
## Network
Loopback is a route, not identity. Authenticate local endpoints and IPC where privileged; constrain remote exposure, TLS and allowed origins. Network grants name normalized scheme, service identity, host and permitted port/path; enforce after DNS resolution and on redirect; block unsupported private-network access rather than assuming URL string filters suffice. Do not add an external relay without explicit trust and data retention policy. No direct worker egress when brokered mode required. Treat Tailscale as transport, not the application identity.
