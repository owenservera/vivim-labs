## Grant and replay binding
1. E browser key: nonextractable P-256 ECDSA CryptoKey in IndexedDB; DER signature conversion for Node verifier; existing grants call requireExisting so lost key fails rather than silently regenerating. E grant ID/origin/user/kind metadata persisted in localStorage, session ID in transport memory.
2. B creates pending grant from verified challenge; PC owner limits scopes; revoke is permanent check in validateGrant. PWA asks relay:read,relay:write,control:read,control:execute; devices:read is not among these requested scopes.
3. **P0 missing:** authorizeDevice(req,scope) checks only x-vivim-grant-id and x-vivim-device-session against active, unexpired grant and scope. Signature only mints session; it does not bind each request's method/path/query/body digest, current audience, operation ID/nonce or source revision. A copied active bearer can authorize any in-scope endpoint within session lifetime. Host executor claim-once protects one plan replay but NOT arbitrary new plan or private reads. Require B-owned per-request proof OR stronger jointly reviewed proof-bound session mechanism with real replay denial; E signs exact B canonical transcript. No fake localStorage security assumption.
4. **Residual XSS:** nonextractable key prevents export but same-origin script can invoke sign(). CSP has script-src 'self'; forbid injection, unauthorized dynamic scripts, unsafe HTML and grants via semantic hints. Origin/CSRF independently validated by B. Confirm forwarded user identity cannot be spoofed.
5. Explicit negative matrix: foreign localhost 200, stolen session, replay nonce, expired/revoked scope, altered body/query and confused-deputy origin must fail; unknown result stays uncertain, no automatic reissue.
