# 05 — Interface atelier
Designing an experience, not a new application. VIVIM keeps the universal chat bubble, existing Host/Studio ownership, and TierFlow as the single visual runtime.

## The visual language
- **Ink:** observed evidence — crisp, connected, inspectable.
- **Mist:** unknowns — visible gaps, never silently filled.
- **Glass:** a hypothetical — seductive, translucent, clearly not real.
- **Threads:** lineage — relationships across revision and repository.
- **Pulses:** test receipts — visible only where execution was actually observed.
- **Paper:** a human decision — durable, attributed, reversible through an explicit owner process.

Color alone must never carry truth; labels, shape, keyboard and screen-reader semantics remain mandatory. Avoid a map that looks like a spaceship dashboard but teaches nothing.

## One screen, four depths
```text
┌─────────────────────────────────────────────────────────┐
│  Chronicle                   Not run • Sources not loaded│
│                                                         │
│  [Source A]   [Source B]   [+ version]    [Ask HQ]       │
│                                                         │
│  ┌───────────── FUTURE RESULT STAGE ─────────────────┐   │
│  │       (empty until an authorized request)         │   │
│  │                                                    │   │
│  │  Story  →  Map  →  Contracts  →  Exact evidence    │   │
│  └────────────────────────────────────────────────────┘   │
│                                                         │
│  “Choose revisions. Nothing has been compared yet.”     │
└─────────────────────────────────────────────────────────┘
```
This is an **illustrative concept sketch**, not existing UI or a tested layout.

### Depth 0 — One sentence
“Three implementations may correspond to one old capability; none has accepted runtime parity evidence.”

### Depth 1 — The story
A short, lucid explanation ordered by how a human would ask the next question: origin, transformation, evidence, uncertainty.

### Depth 2 — The map
A pan-and-zoom visual of capabilities and version pins. Show uncertainty as architecture, not just footnotes.

### Depth 3 — The laboratory
Exact pinned blobs, source ranges, contract fingerprints, test execution receipts, provenance chain, trusted owner decisions, export.

## Four interaction sketches
1. **Drag time, keep meaning.** Scrub revisions; the capability remains anchored while its implementation shape morphs. The “same capability” line is dashed unless proven.
2. **Long-press a claim.** The claim blossoms into evidence cards and a precise statement of what has *not* been verified.
3. **Tap the empty horizon.** Before any run, the view teaches available inputs and permissions. It does not preload real repositories.
4. **Split the world.** Compare observed source history with a hypothetical proposal side by side, explicitly labeled *fictional design*.

## Three emotional goals
- **Wonder:** “I can see the architecture breathe.”
- **Comprehension:** “I can understand why this matters without reading 50 files.”
- **Trust:** “I can always find out what supports that claim.”

## What not to create
No new editor, no competing TierFlow publisher, no standing repository watcher, no unexplained green score, no auto-approve/auto-merge button, no cinematic animation that obscures missing evidence. The dream is a *projection* of typed truth, not a second application with its own invented authority.
