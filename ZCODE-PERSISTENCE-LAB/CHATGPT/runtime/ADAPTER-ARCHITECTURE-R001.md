# R001 — Operational adapter architecture
2026-11-28 | Design proposal based on actual R004 source inspection; no code changes, builds, live execution or acceptance claims. Companion: GENESIS-CODING-HARNESSES-R001.md.
## Design boundary
Kernel owns goals/tasks, logical agents and incarnations, scheduling, model allocation, durable state, knowledge, typed composition, verification policy, learning and reconciliation state. External adapters supply observations, access to capabilities, controlled execution and independently observable receipts. Do not introduce a second scheduler, registry, graph, mailbox or effect authority. Product Host remains sole VIVIM effect authority. Adapter discovery is not authorization. Native pure operators are not adapters. A model proposal is data, not a grant.
The existing routing_driver::Backend and routing_adapter::Envelope/AdapterReceipt are inference-specialized (provider/account/model/thinking/usage/reservation); do not force non-inference calls into token billing or fake providers. Preserve them and add a general typed operational port only where required, reusing existing effects.rs intent/fencing and Host receipt semantics. executable_bridge.rs and adapter_mailbox.rs are transport mechanisms, not proof of a live vendor implementation. Existing local_effect.rs supports one narrow content-addressed JSON publication. Existing projection/composition/assimilation/recipes remain owners, not replacement adapters.
## Operational ports (logical contracts; not separate processes or crates)
P01 Intelligence: model/profile discovery, capability/quota/availability, request/stream, usage, cancel/reconcile. Existing routing contracts and synthetic/mailbox/executable bridge; real authorized binding qualification pending.
P02 Agent/harness session: discover/create/attach/resume/fork, inspect current state, stream cursor, steer with ack, inject versioned context, interrupt, export/import permitted session artifacts, generation fencing. Use VIVIM coding-harness family (OpenCode/ZCode/Codex/etc.), avoid a parallel native process owner. Model routing and session continuity distinct.
P03 Host execution: discover/describe allowed commands, plan/admit/invoke, bounded process/file/terminal/build actions, observe/reconcile/verify; VIVIM ASDF/native Harness. Existing effects intent + narrow local publication, general Host binding missing. No unbounded shell passthrough.
P04 Repository: snapshot pin, tree/list, blob/diff/history, isolated proposal/patch, expected-head validation and reviewed commit, readback/rollback proposal. GitHub connector + local Git under Host; no branch creation in this pilot, no force push, no destructive reset.
P05 Knowledge/source acquisition: Context7 resolve/query, source/official docs fetch, provenance and version pins, content digest, incremental refresh, normalized source facts. Source content untrusted; no auto-execution. Reuse Product source and graph index.
P06 Capability/tool registry: discover/search/describe exact schemas, eligibility, route/dependency refs, staged mapping, validated publication via Product; consume existing canonical 3000+ atomic register; no shadow registry. MCP, CLI, GPUI projections of same owner.
P07 Workspace/artifact: scoped workspace allocation, immutable artifact refs and content hashes, files/patches, checkpoints/log export and migration, readback/retention. Existing projection/payload owner stays canonical; external workspaces are projections or independently referenced artifacts.
P08 Event/communication: ordered per-stream events, cursors/replay/gap, mailbox send/ack, owner steering, lane-to-lane handoff, subscriptions. Existing durable mailbox and lifecycle remain authoritative; adapters bind external sessions and UI to it. Never claim remote steering delivered without ack.
P09 Verification/test: independent fixture/oracle runner, compiler/test receipts, negative/holdout validation, verify repo/artifact readback and reject producer self-certification. Existing Oracle/custody/assimilation acceptance reused.
P10 Environment/resource: installed tool versions, process identities/liveness, CPU/memory/disk/I/O, wall time, quota observations, capacity and health; existing resource/process_observation/service partial; Host provides bounded observation, unknown != zero. Scheduling stays kernel-owned.
P11 Identity/authorization: scoped account/credential handles, grant/policy observations, approval and denial, revocation; use Product Host and existing ingress/authority. No credential values in kernel logs, model context, or repository. No grant generated by adapter.
P12 Owner/control plane: goal submission/versioning, pause/cancel, inspect state, approve bounded effects, live observability and evidence, human correction; existing ingress/projection, expose via incumbent Product clients. Do not create independent workflow state.
Optional later ports: device/remote workspace, external applications/services, notifications, specialized computational engines. Prefer P03/P06 composition and existing Product capability bindings over vendor-specific kernels. Internal storage, clock/supervisor and knowledge persistence are native responsibilities; only add platform/storage interfaces when portability or fault testing requires them.
## Common contract
Descriptor: stable adapter id, kind, version, instance/host fingerprint, capability/schema revisions, operation semantics, supported observations, effect class, required grant, limits, cancellation/reconciliation semantics, evidence and health. Typed request: operation/version, input ref/digest, goal/task/agent/incarnation/lease generation, request/idempotency key, deadline and resource reservation, exact binding/grant ref, expected observation revision. Observation: origin, subject, value/unknown, freshness, sequence/cursor, digest, disclosure. Receipt: request/native correlation, binding, observed status, output refs, usage/resources where applicable, independent evidence refs; distinct success/verified/failed/unknown. External streaming events use epoch, ordered cursor, bounded payload/ref, gap and acknowledgement. Dispatch only after durable Host admission; uncertain effects reconcile original identity without blind retry; cancel request is not proof of stop. Pure computation/read operations can use cache on exact immutable inputs; do not cache mutable state indefinitely or replay effects.
## Genesis priority and tests
First close end-to-end P02/P03 using existing P01: one free authorized OpenCode or ZCode session with exact installed fingerprint, accepted native ID, live incremental output, steering ack, cancellation and observation after restart. No model activation until prior unsettled test/session records reconciled and scope/budgets verified.
In parallel wire read-only P04/P05/P06/P07 so existing Context7 and pinned source packets can be read, indexed and staged into isolated proposals. Run P09 independently against exact pinned inputs; P08 provides session/agent communication; P10/P11/P12 enforce observability/control.
First workpiece: consume existing source packet, map exact session discovery/read contracts to existing atomic IDs, generate typed route proposal, reject stale revision/malformed schema/duplicate/unqualified publication, verify with independent fixtures, stage and commit only under authorized Host and current Git head; repeat on another provider and measure deterministic reuse. Start with one logical agent; scale to <=10 active inference lanes only after live control verified. No paid fallback.
Acceptance per port: exact identity and version; supported/unsupported/unknown explicit; positive operation and denied/stale/invalid input; bounded resources; restart/reconcile without duplicate effect; cursor/ack for streamed interfaces; independent postcondition; no bypass of Host; repeatable evidence pinned to source and installed version. No source-only pass. R004 historical native test status remains unresolved; this document does not change the 50-gate tracker.
