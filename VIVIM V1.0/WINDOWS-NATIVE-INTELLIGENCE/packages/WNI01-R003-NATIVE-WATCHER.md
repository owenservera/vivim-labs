# WNI01 R003 — native observation primitive and loss-aware journal

Actual source: rust-starter/src/watcher.rs and journal.rs. One-shot nonrecursive ReadDirectoryChangesW with overlapped event, aligned 64 KiB buffer, fixed-drive canonical path checks, bounded wait, cancellation followed by completion drain, explicit gap, and scoped relative record decoding. No permanent watcher, no admin privilege, no directory content reads. Real Windows owned-fixture test and portable journal tests provided. This primitive intentionally does not grant paths or publish raw names. A production adapter must verify the opened handle's identity and active scope, filter protected names, and use existing Host supervision with bounded lifetime (driver cleanup may block). Directory replacement races are not completely solved; no public MCP registration until addressed. One-shot timeout is NOT a continuous change stream; every new observation needs a new generation or explicit gap, never pretend no missed events. Journal pages are bounded and signal stale cursor, overwrite, source loss and generation rollover; baseline completion must be independently verified by existing Host/HQ. Journal is memory-only; persistent checkpoint/graph commit wiring remains pending.

Context7 /microsoft/windows-rs/0.61.0 returned generic feature examples, so exact IO signatures were checked against Microsoft Learn and windows-sys 0.61.2 docs: https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw ; https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex ; https://docs.rs/windows-sys/0.61.2/windows_sys/Win32/Storage/FileSystem/fn.ReadDirectoryChangesW.html ; https://docs.rs/windows-sys/0.61.2/windows_sys/Win32/System/IO/fn.GetOverlappedResult.html . No Rust compiler on cloud container; compile and OS tests UNRUN. Feature additions use existing windows-sys, not new runtime dependency. Native adapter is source candidate, not released.
