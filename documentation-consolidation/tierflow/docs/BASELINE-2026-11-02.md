## 5. Coordination bus registration (HQ `hq.sync-bus/2`)

Registered in HQ's machine-local spaces registry (idempotent commands):

```sh
bun C:/0-BlackBoxProject-0/repos_hq/scripts/sync.mjs space add \
  --name tierflow --repo C:/0-BlackBoxProject-0/vivim-ui --agent tierflow-agent
bun C:/0-BlackBoxProject-0/repos_hq/scripts/sync.mjs space add \
  --name repos-hq --repo C:/0-BlackBoxProject-0/repos_hq --agent hq-agent
bun C:/0-BlackBoxProject-0/repos_hq/scripts/sync.mjs space add \
  --name vivim --repo C:/0-BlackBoxProject-0/vivim-web-harness --agent vivim-orchestrator
```

Evidence:

- `space list --json` returns all three spaces.
- `tierflow-agent` sent `tierflow-online` notes to `repos-hq:hq-agent` and
  `vivim:vivim-orchestrator` (exit 0).
- `check --as hq-agent` → exit 3 (11 unread at that moment).
- `check --as vivim-orchestrator` → exit 3 (4 unread).
- `inbox --as tierflow-agent --json` → 10 unread broadcasts, every record
  `authority: "coordination_only"`; the read advanced the cursor (read receipt,
  not an acknowledgement).

A bus message is coordination, never permission. No message on this bus grants
an effect, an approval, a send, or execution authority. Registration and reads
were performed by the integrator; the adapter implementation and its tests are
a separate lane.

- It does not claim HQ-specific behavior inside the universal tiers; the
  adapter boundary is verified separately.
- It does not claim the performance numbers are comparable across machines.

  the known `lintProtocol` signature defect is still present and unpatched.
