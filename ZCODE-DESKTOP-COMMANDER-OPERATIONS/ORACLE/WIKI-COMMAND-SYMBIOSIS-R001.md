## Decision in one paragraph
**Recommend Option A + Option B as one narrow vertical slice, followed by Option C.** Keep *one shared composer*, but make its mode and authority explicit: **Explore / Wiki** is ambient, read-only, always safe to type; **Act / Command** is deliberately selected or invoked by a specific Wiki action. A selected Wiki page/section becomes a source-pinned, permission-fenced *context candidate*, not an approval or a command. The existing catalog/NLCL/VLANG command compiler turns an explicit request into a typed Host plan; the incumbent dispatcher/approval/journal owns all effects; the Wiki and Activity show the verified receipt and current content. No new parser, command engine, graph, action registry, agent scheduler, permission store or journal.

## Conceptual symbiosis — a continuous, trustworthy triangle

1. **Wiki = what exists, what it means and why.** Displays actual concepts, pages, current source revisions, command capability descriptions, readiness and outcomes. Ambient Wiki follows human *and authorized agent* draft text with no effects; a user can choose/pin a specific page without auto-navigating on every character.
2. **NL interpreter = what the user intends.** Existing NLCL/VLANG/catalog/typed Rust projections resolve command candidate, target, slots, ambiguity, scope, current version and readiness. It takes *selected Wiki context* as a typed hint only after deliberate selection, not raw Wiki text as instructions.
3. **Command surface = what may happen.** An explicit Ask-to-Act/Review transition yields an inert plan; Host alone validates grant, actor, source freshness, exact target, risk and digest, then approves/executes/receipts. Safe R0 reads can return a result; R1+ mutations require the existing explicit approval path. The effect is never triggered by Wiki suggestions or partial typing.
4. **Verified feedback returns to Wiki.** The actual persisted Wiki/journal/graph/revision and Activity receipt update the same focused page. A claimed action is not an observed effect; a receipt may prove a historical event, not necessarily ongoing truth. Failed/uncertain/denied states remain visible with no fake success.
5. **Reprogrammability later = authorized reuse.** A tested command or recipe can be explicitly remembered, edited, revoked and replayed under current input/permission/version checks; no cached grant and no automatically self-mutating VLANG/compiler code.

### Recommended mode model
- **Explore (Wiki):** ambient search/semantic suggestions, a stable selected canvas and up to three dynamic topic cards; read-only by default. Clicking a page changes focus only. No submission or provider call on typing. A pin retains the chosen page while ambient suggestions continue changing.
- **Act (Commands):** user taps a visible `Use in command` / `Edit this section` affordance **or** explicitly switches mode. Keep draft, caret, focus and verified selection; create a *new, deliberate intent envelope* for a typed Host plan. Show action/target/arguments/source revision/risk/readiness; clarify unsupported or ambiguous intent. Never inherit read permission as write permission.
- **Build/Inspect (visual reprogramming):** select an actual registered visible UI element, then use the existing VEC preview/Activate path; no Wiki mutation occurs merely by selecting a rendered Wiki panel. VIEW ALL is optional progressive disclosure, not a second engine.
- **Talk/providers and future Dev:** separate explicit destinations; never silently send a Wiki query to a signed-in provider or convert ambient text to a development task. A later PWA `Request a product change` intentionally admits work as PV-14 through the canonical shared registry.

A single composed input can be reused across modes, but **mode changes are explicit user decisions**; the same utterance may have different safe affordances, never different hidden side effects.

## Three high-risk integration seams (Planning should investigate before proposing NEW code)

1. **Wiki focus identity and grant:** a Wiki `wiki:page/section` ID, an R003 hub alias (`wiki.home`), and an HQKG node are not necessarily the same object. Ground exact accepted mapping to existing `wiki-semantics`, source-digest, current actor scope and native query-scoped authority. NEVER use fuzzy match for execution target.
2. **Shared semantic envelope:** `composer-assist` currently gets command/catalog slots and Wiki prefixes, but the first-contact Wiki typing route is separate. Design a *thin* read-only focus/intent adapter into existing Host parser and Rust projection. No new global command parser, no raw system prompt string that grants authority.
3. **Effect and visible readback:** the first-contact mode intentionally blocks Send. Explicit Act must use the existing paired/authorized Host plan/approval/receipt, and the Wiki must reconcile against the actual persisted source; current selected focus and editor draft cannot be lost due to rerender. A plain HTTP 200 or `source_wired` catalog flag is not a verified user-visible success.
