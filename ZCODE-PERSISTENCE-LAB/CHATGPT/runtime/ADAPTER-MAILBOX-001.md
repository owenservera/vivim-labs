# External adapter mailbox and fair reconciliation

Baseline 32ff11ad1fed1b5ef8131218c060d4fc6eeda46e. Source-only, no execution.
- Local asynchronous backend with manifest bound to store, adapter, provider and account. Outbox packets pin input and claimed envelope; explicit one-shot take is durably recorded before input/send authority is returned. Reopening, replaying or missing the original claim never reissues permission. Actual receipt is immutable and can be settled after late completion. Usage overruns are not silently dropped. A mismatched actual identity still requires trusted charge-only reconciliation.
- Driver now passes the committed claim envelope, supports asynchronous publication, skips unsupported entries and rotates a persisted advisory cursor across eligible handoffs. Cursor loss cannot restore authority. Disabled bindings remain discoverable for reconciliation.
- CLI: kernel <store> routing-mailbox create <fresh-mailbox-root> <config.json>; inspect <root>; step <root> <limit>; take <root> <handoff-id>; submit <root> <receipt.json>.
- Security boundary: trusted host bridge only; not an untrusted adapter sandbox, no automatic provider transport, credentials, or network request. File system and external agent custody must be provisioned. Take is an authorization snapshot, not atomic with an external provider send; bridge must obey deadline/cancellation, never retry an uncertain send. Missing packet after committed kernel claim remains unknown; no blind repair. Mailbox record retention is bounded by explicit capacity and not yet archived automatically. Actual integration and qualification remain R08/R09 partial.
