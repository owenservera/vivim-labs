# 08 — Unanswered questions worth keeping alive
These are provocations for future thinking, **not approvals to plan or execute**.

## Ontology
1. What is the smallest thing that deserves a persistent capability identity?
2. When is a port “the same capability” versus a successor inspired by it?
3. How should a capability be represented when ownership changes but behavior does not?
4. Can architecture keep a memory of rejected alternatives without confusing them with shipped code?
5. What counts as a meaningful version outside Git — device behavior, contracts, schema, provenance?

## Beauty and comprehension
6. What is the single most compelling 10-second interaction we could invent?
7. Can an uncertain answer look better than a false “100% migrated” dashboard?
8. Does the most powerful UI involve a map, a timeline, a story, or a conversation?
9. How should complexity collapse gracefully from desktop to thumb-sized PWA?
10. Can a newcomer feel the shape of the system before learning any package names?

## Intelligence and agency
11. Which tasks should the agent recognize natively without maintaining extra prompts?
12. How can the agent ask for precisely the minimum source authority?
13. How should a human correct an incorrect lineage claim without rewriting history?
14. Could future HQ explain *why it chose* one comparison method over another?
15. How do we make refusal beautiful and useful rather than obstructive?

## Computation and verification
16. Can counterfactual reasoning be made structurally impossible to confuse with observed results?
17. Can every important statement carry a machine-checkable chain to source or test?
18. What should never be cached, even if caching would make the tool faster?
19. What is the smallest offline bundle that can reproduce a comparison honestly?
20. How would we know the system is becoming more truthful, not merely more fluent?

## Strange futures
21. Could a capability have a “biography” that outlives any one codebase?
22. Could an architecture become a teaching environment that explains itself in real time?
23. Could a team compare its *intentions* across eras without judging people for old decisions?
24. What would it mean for a piece of software to have an enduring sense of its own origins?
25. What is the first idea here that sounds absurd today but will feel obvious later?

## Garden rules for future contributions
- Capture ideas with a new `VL-*` ID; never rewrite the past to make a prediction look right.
- Separate **inspiration**, **hypothesis**, **research evidence**, **decision**, **implementation**, **executed test**.
- Celebrate contradictions and abandoned possibilities.
- Promote an idea into an approved work order only in a later, separate, explicit owner decision.
- Keep this space generous, strange, humane and source-honest.
