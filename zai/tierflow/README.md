# Repository lane — tierflow

**GitHub:** `owenservera/tierflow`; **existing local owner folder:** `vivim-ui`.

**Authority:** independent, domain-neutral visual grammar, command IR, component catalogue/renderers, local revision/replay, adapters and 3-tier runtime. Harness remains VIVIM's current live UI publisher and owns all Host/provider effects.

## Lane work

- Map visual World, canonical document, legacy surface and Harness `vivim.ui-surface/1` as **different contracts**; identify compatible overlap and unique behavior.
- Compare built-in TierFlow UI, component vocabulary, device projections, storage/revision models and Host/mobile renderers; choose composite best of breed without silently aliasing schemas or producing a second live publisher.
- Prove exact consumers for bundled `.hq-tool/` and checked-in generated `wiki/`; regenerate through the existing HQ generator before considering retirement.
- Preserve the independent Bun server and tested TierFlow runtime; distinguish mounted routes from source-only adapters and fixtures.
- Record blockers for accessibility, visual parity, action/authorization boundaries, rollback and device acceptance.

## Required evidence per round

Component-by-component crosswalk, overlap/difference decisions, import/route/packaging proof, effect and revision authority mapping, source SHA, test exits, retained unique features and precise next integration edge.

## Guardrails

No separate product Host or Android app; no new TierFlow-owned provider effects; no deleting `.hq-tool` or `wiki` until install and regeneration/consumer checks pass. Preserve domain neutrality.
