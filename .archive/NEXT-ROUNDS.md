# Multi-turn continuation — archive-first VLANG protocol reconciliation

**Scope:** research and code comparison, not a claim of implementation. This is a work order for later turns and does not supersede the living R000 MASTER.

## Round 1 — Provenance and deduplication without deletion
Read the archive catalog, compare duplicate and time-separated Git trees, extract chronology and origin SHA of each semantic grammar/protocol version, and record conflicting vocabulary without discarding either side.

## Round 2 — Canonical inline Rust/TS annotation grammar
Examine `@hq:` v1, typed v2, SCF v3 proposals, old `@v.` examples and Rust `///` declarations. Specify exact parser scope, binding, escapes, comments-as-strings, macro/attribute interactions, generated code, JSX/TSX boundaries, and negative conformance vectors.

## Round 3 — Source identity, incremental compiler and graph projections
Compare stable IDs, rename lineage, source hashes, dependency invalidation, semantic IR and registry. Reuse existing HQ/HQKG and Wiki journal; no second semantic graph or indexer.

## Round 4 — Proof, evidence, context and agent lifecycle
Reconcile claim assurance tiers, test/receipt lineage, bounded source-context packets, agent SDK lifecycle, stale claims, interrupted runs and conflict disposition.

## Round 5 — Rust adoption and product wiring
Map current ARBOR Rust/Host/VEC/PWA/Wiki capabilities against the final contract, using actual source and current HEAD. Plan minimal inert Rust reducers/compilers and single Host authority path. No mass annotation without parity.

## Round 6 — R001 source implementation and real conformance
After protocol decisions are locked, edit ARBOR on main only with source-grounded assertions and real tests. Report genuine green/failed/unrun evidence, never synthetic proof.
