## 3. Critical defects and challenges in our *own* verifier

1. **Wrong graph interface.** F expects one unversioned JSON {nodes,edges} projection with local IDs and `sourceSha`. E publishes `repos-hq.hqkg-exchange/1` JSONL with `hqg1:` IDs and a separately persisted `.hqj`; the Rust query CLI has its own output. F must independently correlate all three without inventing a new graph writer.
2. **False cross-domain success.** F currently accepts any directional two-edge code→KB→command path by shape; it does not validate source hashes, semantic B identity/version, C registered handler, real query equivalence, edge evidence class/owner or full compiled source→semantic→command chain.
3. **Weak wiki equivalence.** F currently checks whether wiki text contains three IDs. That is not proof of linked meaning, functioning Markdown links, status/authority correctness or original HQ generation. D is closer but must itself be checked.
4. **D↔E metadata mismatch.** E emits `source_path`, `source_commit`, `content_sha256` and edge `evidence_class/evidence`; D's `sourceSafe/hasEvidence` checks `source_repo/source_sha` and `link_status/evidence_ref`. Source node kinds (e.g. `source-root`, `semantic_id`, `operation`) also need explicit domain classification. **Do not silently rename fields in F and certify fake compatibility**: demand a versioned owner-authorized read projection or equivalent direct proof.
5. **A/B/C→E mismatch is deeper than envelope schemas.** A uses an absolute Git-root scope, versioned `vivim.index-intent/0.1` project ID and SHA-256 source hashes; E expects repo-relative root prefixes, `projectId=vivim` and `vivim.wave1.source-records/1`. B uses numeric HQ project ID, bounded SQL rows, reference-only source targets and uncertain links. C uses `hq.action:` candidates and `semanticId:null`. E needs matching `semantic_id` in B/C plus current/wired statuses. Crosswalk cannot assert what isn't verified.
6. **Unsafe subprocess design.** `spawnSync` with allowed binary `node/bun/cargo` and `shell:false` still permits arbitrary JS or cargo build scripts via trusted manifest. Lexical prohibited-word regex is not an effect authorization boundary. Native import tests must run **only** via allowlisted bounded recipes on isolated disposable DEV journal copies; raw owner file/DB edits and executable NL actions remain out of scope.
7. **Containment/privacy gap.** Lexical `relative()` checks do not protect against symlinks, TOCTOU or a malicious redirected report directory; stdout/argv/stack traces may contain secrets beyond simplistic key-value redaction. No unchecked report re-use, path traversal, unbounded logs, private KB upload, or journal overwrite.
8. **Self-attested green.** The input manifest can set `indexed:true`, `reset.verified:true`, fabricated cases and manually supplied placements. Rust query/journal digests are not independently tied to the same source tree, index revision, compiler and wiki.
9. **Wrong unit of coverage.** F's initial blocked 46 is a checklist failure count. It lacks eligible/excluded/ignored/truncated root denominators, source bytes, KB row/alias/semantic link denominators, command route coverage, graph orphan/link denominators, wiki pages, and unknown-vs-absent/STALE classifications.
10. **No meaningful incremental/lifecycle proof.** Rust import is additive; unchanged no-op cannot prove deletion/rename retirement. F also does not prove source drift, revision collision, CAS rollback, stale source rejection, crash atomicity, old-run isolation, semantic status changes, owner collision or contamination of PRODUCT by DEV.
11. **No native Rust-vs-SQLite decision.** The nine existing DEFER_MEASUREMENT rows contain zero actual scan/query/import/FTS/restart p50/p95 measurements, resource budgets, ownership/atomicity comparisons or migration cost. “Rust everywhere” is **not** an evidence-based conclusion.
12. **Language hazards are broader than HQ scoring.** Historical Harness audit demonstrates negators silently discarded into approval-requiring R1/R2 candidates, while C's new inert guard is a separate route. Truth requires independent comparison of both paths, quoted provider payloads, Spanish unsupported cases, multi-clause contradictions, missing slots and wrong targets. Do not authorize execution to test routing.

## 6. Acceptance law: independent, bounded, reproducible

A complete F pass requires (a) real owner-machine scoped reset and N-root denominators, (b) source-byte/Git/source-scope pins; (c) real A+B+C semantic linkage with one verified compiled comment/handler; (d) Rust HQKGX1+journal+read-only Rust CLI with independent evidence; (e) original HQ wiki regenerated from that graph and D independently graded; (f) native Node/Bun/Cargo/SQLite receipts, replay and failure safety; (g) recorded negative-intent corpus, placement benchmarks and privacy/owner boundaries; (h) machine+human reports showing every unknown/truncation/supersession. Each artifact carries schema, producer, source digest, tool/platform version, command/exit and evidence class; zero-cardinality never means 100% coverage.

**PASS** only if every foundational gate has authentic independently checked evidence and no unresolved critical unsafe or incorrect-integrity finding. **PARTIAL** only for bounded nonfoundational coverage with honest denominators and no foundational missing domain. **BLOCKED** for any missing native/root/compiled chain/wiki/ownership source or tamper/refusal failure. **UNVERIFIED** is not **ABSENT**, **DECLARED** not **WIRED**, **STATIC** not **OBSERVED**, and approval-required does not make a wrong negative intent safe. Never execute effects or promote source comments. Product release is not established by DEV proof.

## 7. Improvement over the central assumptions

A single common *producer schema* is **not** the sole goal. The reliable abstraction is a **proof-carrying, versioned read boundary**: source-native A/B/C record envelopes remain untouched; E alone lowers approved typed records and owns the Rust journal; F validates source and projection relationships independently using immutable receipts. D proves human-facing wiki meaning, not number of pages. This avoids false completeness, a fourth registry, a replacement compiler, a second SQLite writer, premature Rust-native FTS migration and a second UI/Host effect path.

The missing-link ledger should distinguish: missing in eligible source, unseen due to exclusions/truncation, not-mapped in E, not surfaced in D, declared-but-unwired, observed-but-untraced, authority-unknown, stale/revoked, unsupported and prohibited. Prioritize by severity × downstream reach × evidence confidence, **not** raw checklist count. Re-run after the Master handoff; its future integrated changes can resolve or invalidate every source-only hypothesis.
