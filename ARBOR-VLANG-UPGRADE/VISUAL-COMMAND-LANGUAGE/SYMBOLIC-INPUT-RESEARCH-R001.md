## Findings
D-217 defines 17 glyph families: / @ # ! ? + - & $ * % ∆ ✓ = ^ ~ →. Lexer attaches @ / # $ to following words; normalizes Δ/∆, ✔/✓ and routes ->, =>, >, →. Token projection carries source start/end, family, role and notes, with slot attribution; effect projection provides risk/provider/gate. Historical symbols source assigns color hints emerald/amber/teal/rose/orange, but these are not mandated VCL palette. The historical ! force wording says skip confirmation card; current Host authority and exact approval contract must prevail. ✓ is confirmation input, not proof of success. No exact @rex mapping found; @ is reference, with @peter and @this verified examples. Original design docs distinguish conceptual syntax from complete execution.

## Proposed VCL integration
Three equivalent presentations of same typed semantics: natural language, symbolic shorthand, interactive visual graph. Do not require symbolic input or silently replace text. On a valid prefix at caret, produce inert discovery UI from scoped live catalog/registry: / command menu; @ reference picker; # tag picker; $ binding picker; ? inspection menu; + attachment/add target; → route destination; others as appropriate. Filter on typed suffix, Tab stages selection, second Tab advances next slot, VIEW ALL exposes scoped catalogue; Esc dismisses. Exact keyboard behavior reconcile existing 2-TAB spec. Pointer, touch, keyboard and accessibility share typed UiIntent; selecting never executes. Render recognized glyph as token/icon/wrapper/adornment using existing 47-axis VCL registry. Preserve symbolic source spans, source revision, original user text, quote/IME and caret. Reparse after selection. Examples /send @this → @peter and /list & /rules are historical examples, not current capability promises. Mixed natural language + symbols supported only where validated by canonical parser and current catalog. Proposed email UX: / opens allowed actions; selecting email draft yields @ picker for recipient, + attachment picker, provider edge selector for account. No assumed real email accounts or recipients.
