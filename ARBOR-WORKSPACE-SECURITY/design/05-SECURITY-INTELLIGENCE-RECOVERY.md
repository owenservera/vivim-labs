# Security intelligence, response and recovery R002
## Observability
Use existing Host journal, Rust observability and HQKG source-backed projections. Security events are typed records: authenticated actor/device, workspace, operation, resource reference, policy version, decision, reason code, revision, effect status, correlation ID and time. No secrets, auth headers, raw private prompts or cookie material in receipts. Use opaque references and bounded redacted evidence. Journal integrity can detect changes relative to a trusted checkpoint, not magically prevent same-authority rewriting. Protect checkpoints and retention against unauthorized writers.
## Owner security view
Use PWA/TierFlow to display devices, grants, program versions, access decisions, external connections, storage health and recovery status. Trusted security controls must be independent of user-generated render programs. Pending vs committed vs uncertain facts remain distinct. No fabricated live status. Query existing source-backed data, do not build another security database.
## Emergency containment
Owner action revokes sessions and standing grants, prevents new external effects, stops cancellable workers, isolates network access and preserves forensic data subject to policy. Do not delete owner content or silently reset stores. Restart only with validated runtime identity and explicit appropriate authorization. Recovery playbook: lock, preserve, scope, revoke, rotate affected keys, restore verified snapshot, reconcile uncertain effects, re-enroll trusted devices. Avoid remote erase promises for already downloaded data.
## Release integrity
Pin and verify dependencies/artifact digests, signed release manifests, rollback protection and authenticated updates. Keep direct-main policy; use integrity checks and non-destructive compare-and-swap commits. Development checkout never inherits production credentials. CI test receipts must distinguish runtime evidence from static analysis. External public Labs holds design and non-sensitive evidence only.
## Acceptance
Authorized routine operation visible; denied action logged without data exposure; owner emergency isolate stops new effects; journal tamper detectable where supported; recovery validated on clean environment; package tampering rejected; update rollback safe. UNRUN.
