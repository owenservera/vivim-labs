# Cross-session contract — small, source-backed and honest

## One shared truth, not three task lists
Planning creates task bundles, Dev integrates product code, Oracle shapes outcomes and audits evidence. Oracle files hold strategic constraints and recommendations, **never task-state copies**. The historical OWNER-WORK registry exists in local records but is **not verified in connected GitHub main**; do not pretend it is remotely accessible. Planning must first resolve the actual shared canonical work source and make any new path explicit before treating it as authoritative. A Dev/Planning folder index is not a substitute.

## Minimal message contract
A handoff has only: **source command/OW identity, desired outcome, evidence pointer, repo+source SHA, next role/action, acceptance signal, acknowledgment**. Add security/ownership detail in the existing bundle rather than each role's SITREP. Each ChatGPT session refreshes shared state explicitly; a GitHub commit is not proof another ChatGPT session read it.

## The three distinct loops
1. **Product UX:** PWA draft -> first-contact Wiki read is *ambient* and read-only; it is **not** permission to create a development task.
2. **Development:** an **explicit** build/modify intent or owner-confirmed directive -> scoped Host-authorized work ingress -> Planning -> Dev -> tests -> release -> phone proof.
3. **Optimization:** proved recurring pattern -> reusable tested Rust capability/recipe -> measured decrease in calls and owner touches; preserve fallback when not proven.

Never conflate source implemented, tests authored, tests run, remote push, deployed Host, real phone observed, and owner accepted. Keep traceable request IDs and revision fences. Host retains effects/approvals/receipts; no secret/private text copied to public logs; no extra permissions through a status file.
