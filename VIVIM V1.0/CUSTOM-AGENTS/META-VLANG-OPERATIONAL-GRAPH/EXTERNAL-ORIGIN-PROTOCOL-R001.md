## Origin record
- Stable external project/component ID, publisher, canonical URI, published version if established, immutable commit/tree/blob or package checksum, retrieval/review time. Exact upstream path/symbol/span and fragment digest for copied material.
- Relationship: copied, adapted, generated binding, linked dependency, system API call, protocol implementation, research reference/independent implementation, unknown. API use does not mean copied source.
- Incorporation: Labs package/revision, exact overlay base commit/blob, selected and excluded parts, local source/symbol and digest, adaptation/translation, rationale, owner/task and patch lineage. Many-to-many source fragments; retain original origin across local edits.
- Legal/security: verified license/notice refs, review status, redistribution obligations, dependency closure/artifact hashes, source authenticity, compatibility/advisory evidence. Unknown explicit; do not assume license clearance. Reuse existing package/notice/SBOM inputs.
- Runtime: internal capability ID, external API/contract revision, adapter, OS/hardware/SDK requirements, observed support, registration/readiness/actual evidence. Separate OS version, SDK version, windows-sys crate version and runtime availability; never infer deployment or authority from origin.
- Typed evidence relationships from upstream/fragment to local symbol to capability/test/build/release; assurance declared/observed/verified/ambiguous/unknown. Annotation occurrence proves only annotation occurrence. No automatic upgrades, effects or self-grants.
