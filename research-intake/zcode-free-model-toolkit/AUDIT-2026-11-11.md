# ZFree model-schema and known-issues audit — 2026-11-11

**Scope:** source inspection of ZFree in `vivim-labs/research-intake/zcode-free-model-toolkit`, ZCode's published repository schema and Context7 `/zai-org/zcode`, current provider documentation and ZCode feedback reports. **Not** a real-account or local Windows end-to-end run. GitHub source changes are committed separately, with no VIVIM Host code touched.

## Era 1 — Model/schema truth

- ZCode [provider schema](https://github.com/zai-org/ZCode/blob/main/packages/provider/src/config/provider-data-schema.ts) recognizes `openai-chat-completions`, `openai-responses` and `anthropic-messages`. ZFree implements **only** the first protocol; selecting OpenAI Responses or Anthropic in ZCode would fail. ZCode [custom provider configuration](https://zcode.z.ai/en/docs/configuration) documents manually adding a provider, setting URL/API key, and adding a model ID. `free-auto` is synthetic and must be added manually; the local gateway does not write ZCode's private schema.
- [ZCode v3.17.2](https://github.com/zai-org/ZCode/releases) is the newest published release observed 2026-11-11 (release page shows Nov 4, source README says Nov 3). ZFree's `/v1/models` JSON uses OpenAI-compatible `object: list` with `data[].id/object/owned_by`. ZCode selection and token-context behavior are **not** proven by this alone.
- [OpenRouter models catalog](https://openrouter.ai/docs/api/api-reference/models/get-models) returns `pricing`, `architecture.output_modalities`, `supported_parameters`, and reasoning metadata. ZFree now requires literal `:free`, zero prompt+completion **and all additional published price fields**, and text output. Tool-using requests only target models declaring `tools`. This is an eligibility filter, not a guarantee that tool-call streams are valid.
- [OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) uses `reasoning: { effort: ... }` for Chat Completions. ZFree now collapses mutually conflicting ZCode `thinking`, `enable_thinking`, `reasoning_effort`, and `reasoning` fields, then emits the canonical OpenRouter `reasoning` only when catalog metadata declares support. Unsupported provider-specific fields are removed. NVIDIA retains at most one `reasoning_effort` hint; this path is still not device verified.
- ZFree supports one HTTP endpoint, `POST /v1/chat/completions`, including SSE and standard message/tool requests. It has no `/v1/responses`, `/v1/embeddings`, image generation, per-model tokenizer, or negotiated context window. No claim of model-schema completeness across all ZCode protocols should be made.

## Era 2 — Known public issues that matter

| Issue | Observed report | Consequence / mitigation |
|---|---|---|
| [#703](https://github.com/zai-org/feedback/issues/703) | v3.12.3 sent contradictory `thinking`/`reasoning`/`reasoning_effort` params → 400 | **Gateway normalization added**, but real 3.17.2 replay needed |
| [#623](https://github.com/zai-org/feedback/issues/623) | Custom models shown but not selectable due to stale bundled model/effort validation | **Cannot fix a ZCode-side pre-request failure from proxy**; configure `free-auto` as simple custom model and verify picker/subagents |
| [#1454](https://github.com/zai-org/feedback/issues/1454) | 3.17.2 malformed streaming tool-call function name aborts turn | Gateway byte-passthrough cannot repair upstream malformed tool deltas; needs replay fixture and optional schema-aware stream repair, **not yet implemented** |
| [#840](https://github.com/zai-org/feedback/issues/840) | OpenCode Go session header missing from custom clients | Direct ZCode→OpenCode Go integration affected; ZFree **does not** bypass OpenCode's free-client restriction |
| [#93](https://github.com/zai-org/feedback/issues/93) | OpenAI-compatible streamed usage metrics absent if `stream_options.include_usage` missing | ZFree passes the field through if present; cannot force ZCode to display usage without validating parser |
| [#1446](https://github.com/zai-org/feedback/issues/1446) | Agent process can crash after network/TLS error during provider streaming | ZFree prevents a second HTTP response after stream starts; does not solve ZCode's own TLS handling |

These are **user/issue reports**, not proof that every problem still reproduces in the current release or is universally applicable to this gateway.

## Era 3 — Current verification and release gates

### Static fixes committed

- Explicit zero-charge filtering includes auxiliary published prices.
- Reject catalog models with non-text output and require `tools` support for tool-calling requests.
- Normalize ZCode reasoning aliases and map to OpenRouter's published schema.
- Do not issue a second HTTP response after streamed headers/data; close the connection instead.
- Additional unit tests added for zero pricing, reasoning collisions and text capability.

### Remaining blockers

1. No Python test execution by this session: GitHub connector writes succeeded, but local environment had no access to retrieve the private/public repository via raw.githubusercontent.com. Unit tests are *committed, unrun*.
2. No installed ZCode 3.17.2 instance or logged-in OpenRouter/NVIDIA accounts attached to this session, therefore no verified successful ZCode tool call, SSE session or free billing receipt.
3. NVIDIA's authenticated model-list API does **not** guarantee chat-completions support, function calling, a zero balance impact or prototype quota. The opt-in NIM route is marked **experimental**. Real model-specific probes and provider quota/account checks are required before automatic unrestricted use.
4. ZCode custom model is not auto-registered; currently requires **one-time manual UI creation**. There is no supported, verified external configuration automation API. Do not patch its versioned private JSON in place.
5. No capability negotiation for per-model context size, tools schema details, multimodal messages, or provider-specific unsupported fields beyond targeted normalization. Blind fallback can change model capability/behavior; avoid claiming transparent equivalence.
6. OpenRouter free requests are rate-limited; per-model rate limit / account quotas may stop routing. Live published zero model price does not mean all calls succeed or unlimited volume.
7. Authentication is optional for loopback unless `ZFREE_LOCAL_TOKEN` is set; **set it** before relying on the gateway.

Start `python zfree.py serve`; in ZCode 3.17.2 choose custom **OpenAI Chat Completions** with base URL `http://127.0.0.1:8765/v1` and synthetic model `free-auto`. Validate one plain request, one real tool call, long SSE response, reasoning effort switch, 429 retry, exhausted quotas, key unset, and context-window/usage behavior.
