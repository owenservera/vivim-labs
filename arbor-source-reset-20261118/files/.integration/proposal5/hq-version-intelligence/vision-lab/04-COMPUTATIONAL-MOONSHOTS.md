# 04 — Computational moonshots
Unapologetically ambitious **research hypotheses**, not new engines to implement now. Each is compatible in spirit with one Rust native computation core, HQ knowledge, Host effect authority and a TierFlow projection.

## 1. A temporal capability hypergraph
What if the basic object were neither a file nor a module, but a typed relationship among **capability, implementation, source revision, contract, test, owner, decision and evidence**? One capability can map to many implementations and vice versa; connections carry provenance, validity interval and confidence. Reuse the existing knowledge graph. Research question: how can such an index remain deterministic, small and incrementally rebuildable?

## 2. Explanations as proof objects
Every explanation sentence could carry machine-readable support: source nodes, exact pins, inference rules and reasons for uncertainty. The UI could peel a paragraph apart like layers of a geological sample. Research question: what is the minimal explanation calculus that is useful without pretending to be formal verification?

## 3. Change as a causal hypothesis, not a diff
A diff proves changes in source; it doesn't prove *why* or what happened at runtime. Imagine typed causal hypotheses whose supporting and contradicting evidence can be inspected. A smart agent would say “strongly suggests” rather than fake “caused.” Research question: how do we avoid accidental causal storytelling?

## 4. A capability compiler from everyday language
Natural-language request → bounded typed intent → source scopes and pins → deterministic comparisons → structured evidence → optional beautiful projection. Only Host grants access. The parser must be allowed to return “ambiguous.” Research question: can user questions themselves become replayable, diffable, source-independent query objects?

## 5. A decision fossil record
Architectural decisions are usually scattered across Git, docs, chat and reviews. With opt-in sources only, a future “decision layer” could reveal how an invariant emerged or disappeared. Never infer consent to ingest private chats. Research question: what is the useful minimum source set?

## 6. Counterfactuals with ontological firewalls
A separate `hypothetical` data type prevents generated future versions from being mistaken for observed Git commits. Every imagined result carries assumption labels, not source attestations. Research question: can the UI offer spectacular possible-world exploration while making observational truth impossible to confuse?

## 7. Typed identity through rewrites
Same name doesn't mean same capability; different name doesn't mean different capability. Explore a robust evidence-based equivalence language with owner-approved assertions and explicit aliases, conflicts, splits and merges. Research question: which aspects of behavior are stable enough to define continuity?

## 8. Verification topology
Visualize tests as relationships to invariants rather than files. Build a “promise → test → executed receipt → platform” map so green source-only coverage cannot masquerade as runtime behavior. Research question: how to prevent stale or forgeable receipts from becoming fake authority?

## 9. Bounded knowledge, infinite-feeling space
Tiny screens, large histories. Use level-of-detail projections, streaming evidence tiles, canonical digest indexes and memory budgets. Research question: how do we render a thousand-node story on a phone without changing what is true?

## 10. An epistemic type system
Represent `observed`, `proved`, `inferred`, `hypothesized`, `missing`, `unavailable`, `not-yet-run` as types, not prose decoration. Transformations cannot silently upgrade confidence. Research question: can uncertainty be compiled and statically checked across an agent/UI chain?

## 11. Computational gravity around architecture
Some abstractions become hubs because they are good; others because nobody refactored the accretion. Measure dependency fan-out, change churn, duplication and proofs as separate signals. Research question: can “needs attention” be shown without treating metrics as objective architectural judgment?

## 12. Software memory across organization boundaries
Imagine carrying a portable, verifiable, privacy-redacted capability story between repositories or companies. A recipient can verify public claims while private code stays private. Research question: what trust model avoids disclosing too much through hashes, paths or metadata?

### One synthesis
All twelve point toward the same unusual idea: **an evidence-native, time-aware software ontology whose interface can feel like an interactive documentary.** It must never become a second operational source of truth.
