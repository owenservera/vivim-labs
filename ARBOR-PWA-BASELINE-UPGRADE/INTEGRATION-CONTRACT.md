# Shared implementation boundaries
## Invariants
1. Single existing runtime and Host effect authority. The registry describes source-owned instances; it must not execute. Engine compiler output is an inert typed candidate. Installed means validated typed setting -> actual renderer effect -> Host persistence/readback test, not merely declared/applicable.
2. Keep incumbent schemas vivim.ui-surface/1, vivim.ui-document/1, vivim.ui-proposal/1 and ui-config-proposal/1; use explicit compatible evolution if required. Do not create a competing document/store. Separate semantic identity, runtime instance ID, document/view ID and revision. Stable across label/theme changes and reload; bind dynamic instances to source IDs without leaking private data.
3. Prefer a thin source registration/factory adapter at existing mount sites over DOM crawling, static mock inventory or generic wrapper framework. Reuse VEC taxonomy and TierFlow existing node contracts, action refs, data bindings. Map existing native controls at the narrowest real boundary. Register mounted presence/lifecycle honestly, discover unmounted destinations from real definitions. All live components addressable; catalog-only items not rendered as real widgets.
4. Bounded view composition: current 64-node/32KiB limits protect renderer. Partition by existing views, shared component recipes and bounded references. Handle size/depth/binding limits, version compatibility and cycle/duplicate IDs explicitly. Never lift limits indiscriminately. Global settings need explicit scope and deterministic resolution (default -> owner global -> view -> allowed component overrides). No raw CSS/JS/HTML or arbitrary external URLs. Existing approved data refs only.
5. Preview candidate binds exact instance, capability, typed value/order/structure, source revision, scope and relevant data/permission freshness. Host recompiles/validates using actual head, policy and current grant. Explicit approval binds exact candidate; claim once, no auto-repeat uncertain effects, stale compare-and-swap refusal. Full projection readback confirms actual semantics/content, not only HTTP status. Don't store private approvals in browser caches.
6. Keep existing product handlers, pairing, token/session authority, control plan boundary and provider conversation separate. Styles cannot change semantics, disable required safety UI, or grant permissions. Required navigation, recovery, contrast, keyboard, focus, screen-reader, reduced-motion and owner approval remain usable.
7. Restore with incumbent revision publisher and monotonic proof or exact compensating revision; do not reset data, reuse revision IDs or bypass guard. If no safe inverse available, refuse/offer existing authorized history flow. Preserve existing persisted projects, theme, Wiki and journals; explicit migration/read compatibility, no silent resetting.
8. Reconcile same state across desktop and phone via authorized Host projections; desktop read-only routes remain read-only. No second write channel. Local offline capture remains local, with existing synchronization semantics.
