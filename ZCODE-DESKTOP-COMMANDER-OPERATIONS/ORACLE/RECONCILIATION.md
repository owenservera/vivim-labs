# Oracle review — one bottleneck, not a full-project ceremony

At each steering turn:
1. **Check authority:** does the claimed canonical work item exist in accessible GitHub/shared source? If a referenced OWNER-WORK path is missing, mark REMOTE_SOURCE_UNAVAILABLE and do not invent updates.
2. **Trace one request:** PWA input/directive -> authorized ingress -> Planning acknowledgment -> Dev commit -> test receipt -> deployment SHA -> phone observation. Label the first unproven edge, not the whole project BLOCKED by default.
3. **Check truth:** a live source path is not a verified event; an agent role defined is not a running session; an authored test is not PASS; a local HTTP check is not Android proof.
4. **Check collisions:** refreshed GitHub main, actual source ownership and latest bundles. Prefer REUSE/REPAIR over NEW. Never force changes over a parallel agent.
5. **Check optimization:** did this change remove an owner copy/paste, make the PWA the sole entrypoint, safely reuse a deterministic rule, or shorten time to trustworthy phone proof? If none, ask Planning to re-rank rather than add infrastructure.
6. **Communicate the minimum:** one highest-impact steering note with outcome, why current work misses it, measurable acceptance and evidence. Planning owns resulting task decomposition and any registry update. Mark unacknowledged handoff as PROPOSED, not adopted.
7. **Escalate only when needed:** missing authorization, privacy risk, architecture contradiction, or substantial owner choice. Do not request routine sign-offs, repeated priorities or manual cross-session coordination.

Evidence classes are SOURCE_OBSERVED / PREPARED / TESTED / PUSHED / DEPLOYED / PHONE_VERIFIED / OWNER_ACCEPTED; label unknown or unavailable honestly. A reversible failure must have correlation ID, last safe state and rollback receipt.
