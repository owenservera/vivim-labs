**Use ChatGPT NEW CHAT five times.** Paste exactly ONE corresponding message from below in each new chat. Each message points to a complete, already-written role prompt. A link or prompt file alone does not start execution; it is the pasted message plus enabled tools that permits the chat to act.

**Current authority:** [ARBOR #33](https://github.com/owenservera/ARBOR/issues/33), [#32](https://github.com/owenservera/ARBOR/issues/32), [#31](https://github.com/owenservera/ARBOR/issues/31), [R002 strategy](STRATEGIC-AUDIT-R002.md), [R002 manifest](manifest.json), [role/claim board](LANE-BOARD.md).

**How continuous operation works:** Each newly created lane chat should do useful work NOW and create **one hourly automation attached to that lane chat** (where automations are available). Each scheduled iteration refreshes source and claims, works on **one to several bounded, claimed, safe tasks**, independently tests, posts source-proven receipts to existing #33 and moves to the next available task. A scheduled ChatGPT task is **hourly recurrence, not an uninterrupted process**. Older ZCode workflows remain reference-only unless explicitly safety-admitted; model-driven workers require actual live/run/cost checks. The existing central ChatGPT dev automation stays coordinator and is not replaced by five copies.

**Preferred cadence, Europe/Madrid:** L01 :04, L02 :16, L03 :28, L04 :40, L05 :52 each hour (offsets, not current scheduled confirmations). Each lane must check for an existing matching task to avoid duplicate scheduling; confirm enabled task ID, true next run and supported environment. Per-lane automation does not bypass GitHub file claims or Host/provider approvals.

**Execution truth:** `READY_NOT_LAUNCHED` until the pasted prompt actually starts a lane; `RUNNING_VERIFIED` only with actual task/session/model receipts. No automatic five-seat fanout exists merely because the files are committed.

## Cross-lane coordination

Every lane acts through GitHub source plus Labs [TASK-CLAIMS](https://github.com/owenservera/vivim-labs/blob/main/ZCODE-DESKTOP-COMMANDER-OPERATIONS/TASK-CLAIMS.md) with one active owner per file/scope. Use the one existing ARBOR `main` branch; no force pushes or hidden local source writes. No two lanes may "accept" the same task simply by pasting a prompt. Handoffs require actual `OFFERED_TO` and `ACCEPTED_BY` records.

**Allowed tools by relevance:** connected GitHub for cloud coding/commit/issue; Remote Desktop Commander for local *inspection, post-push build/runtime/physical verification*; existing ZCode for bounded no-effect tests and model scouts after admission; current model registry/fallback only; Context7 for current library APIs when implementing; Files/Oracle corpus only under appropriate user authorization; Automations for hourly cadence in each dedicated chat. Don't install or invoke unrelated services just to claim "all tools."

**Critical first acceptance:** real new ChatGPT thread/composer→settled reply→Host journal→native GPUI + Android PWA. Independently, unblock exact-source VLANG safety, the Host-reviewed Work producer and immutable release. L05 certifies receipts and CI instead of becoming a second source integrator.

**Troubleshooting:** If the ChatGPT lane says it cannot open the GitHub link, make it search the connected `owenservera/vivim-labs` repository and fetch this exact path first; if no tools are available, paste the full prompt from the linked file. If an automation fails to create, the lane must report no scheduled execution; don't infer background operation from the instruction alone.
